# Active observability for coding agents

In this cookbook, you'll build a shared Braintrust project that turns coding-agent sessions into recurring insights. Braintrust tracing sends your instrumented coding agents to one project, custom facets classify each session through Topics, and scheduled Loop automations review the evidence and report costs over time.

Along the way, you'll:

- Instrument your coding agents and send their traces to the same Braintrust project.
- Enable Patterns for continuous analysis.
- Install a portable active observability template with the `bt` CLI. The template creates the Topics automation, facets, and Loop automations.
- Collect new coding-agent traces and optionally import valuable existing sessions.
- Optionally use Loop to create and refine facets from your coding-agent traces.
- Optionally send automation runs to a Slack channel.

<Note>
  This cookbook uses the `bt observability template` command. The setup
  verifies that your installed CLI includes it before you configure the project.
</Note>

## Setup

Clone the cookbook and install the latest stable `bt` CLI. This path keeps the installer-managed binary ahead of repository-local or package-managed copies for the rest of the shell session.

You'll need:

- A [Braintrust account](https://www.braintrust.dev/signup) with permission to create projects and automations.
- An [AI provider](https://www.braintrust.dev/app/settings?subroute=secrets) configured in Braintrust for the model used by the automations.
- One or more supported coding agents installed on macOS or Linux.
- Optional: A locally stored Codex or Claude Code session to import.

<Steps>

<Step title="Clone the cookbook and install bt">

```bash
git clone https://github.com/braintrustdata/braintrust-cookbook.git
cd braintrust-cookbook/examples/CodingAgentInsights
curl -fsSL https://bt.dev/cli/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"
hash -r
```

The installer fetches the latest stable release instead of a version pinned by the repository you are tracing.

</Step>

<Step title="Authenticate with Braintrust">

```bash
bt login --oauth
```

Complete the browser flow. The saved OAuth profile lets the tracing plugins refresh credentials without putting an API key in your shell history.

</Step>

<Step title="Verify the CLI">

```bash
command -v bt
bt observability template --help
```

You should see output that starts with:

```text
<home-directory>/.local/bin/bt
Pull and push facets and Loop automations as one active observability template
```

If the first line points into the repository or a package cache, repeat the `export PATH` command in the same shell. If `observability template` is not recognized, run the installer again and confirm that `command -v bt` resolves to the installer-managed binary.

</Step>

</Steps>

You're now ready to instrument your coding agents.

## 1. Instrument your coding agents

Create a project for coding-agent traces, set it as the active project for this cookbook directory, and install tracing for the agents you use. Replace `<YOUR_ORG>` with your Braintrust organization name. The commands below instrument Claude Code and Codex as examples. `bt trace setup` also supports OpenCode and Pi.

```bash
bt projects create coding-agent-insights --org "<YOUR_ORG>" --prefer-profile
bt switch "<YOUR_ORG>/coding-agent-insights" --local --prefer-profile
bt trace setup claude --prefer-profile
bt trace setup codex --prefer-profile
```

Each setup command ends with an instruction to restart the coding agent. The command stores the selected profile, organization, and project in the plugin's tracing route, so every agent you instrument sends sessions to `coding-agent-insights`.

### Instrument your teammates

To include sessions from other people, add them to the `coding-agent-insights` project. Then have each teammate authenticate, select the shared project, and set up tracing for their coding agent:

```bash
bt login --oauth
bt switch "<YOUR_ORG>/coding-agent-insights" --prefer-profile
bt trace setup claude --prefer-profile
```

Repeat the final command with `codex`, `opencode`, or `pi` to instrument another supported agent.

## 2. Configure active observability

Before pushing the included template, go to [**<Icon icon="scan-search" /> Patterns**](https://www.braintrust.dev/app/~/patterns) and click **Enable patterns**. In the **Introducing Patterns** dialog, click **Enable patterns** again to confirm. Leave the optional Slack destination empty for now. Patterns queues an initial analysis and provides the inbox where the discovery automations publish their findings.

Push the active observability template to the active project. Each facet in the template maps to a Topics automation named `Topics`; the push creates that automation if it does not exist and attaches the facets to it. The three Loop automations also become active after the push.

```bash
bt observability template push active-observability-config.json --prefer-profile
```

You should see:

```text
Pushed active observability template to 'coding-agent-insights' (3 facets, 3 Loop automations)
```

The template creates these resources:

- **Coding Agent Context Debt** identifies reusable context that a user had to supply after work began, such as missing repository guidance, architecture knowledge, or environment detection.
- **Primary failure mode.** Classifies the most important visible issue in each run, including unresolved tests, incorrect scope, incomplete work, and wasted effort.
- **Skill invocation failure mode** diagnoses material failures caused by a verified skill invocation, such as using the wrong skill or ignoring its required workflow.
- **Failure Pattern Discovery** reviews the previous seven days of failure-mode classifications, validates recurring findings against raw traces, and creates or updates Braintrust Patterns when the evidence meets its threshold.
- **Coding Agent Improvements Discovery** reviews a 30-day window across Topics, raw traces, and existing Patterns to find recurring opportunities to improve coding agents, then creates or updates qualifying Patterns.
- **Cost Report** produces a week-over-week estimated-cost report by user and summarizes the work represented by the 25 highest-cost sessions. It uses `gpt-5.6-sol` and runs daily at 9 AM in `America/Los_Angeles`; the two discovery automations use `gpt-5.5` and also run daily.

The push stops if a matching resource already exists. To apply a revised template, rerun the command with `--force`; this replaces matching facets by slug and Loop automations by name while preserving any destination actions configured on the target automations.

Topics creates facet summaries asynchronously as traces arrive. The two discovery automations require recurring evidence before they create or update a Pattern, so useful findings accumulate as your team generates more sessions. Cost reports and other automation output are available under **Past runs** in the automation settings.

The project now has a repeatable analysis layer on top of its coding-agent traces. Review its findings on the [**<Icon icon="scan-search" /> Patterns**](https://www.braintrust.dev/app/~/patterns) page.

## 3. Collect coding-agent traces

Restart each coding agent you instrumented, then keep using it for real work. Ask your teammates to do the same. Instrument every supported agent your team uses and add as many teammates as practical. Traces across different agents, tasks, and repositories give the facets and Loop automations more recurring evidence to analyze.

Go to [**<Icon icon="activity" /> Logs**](https://www.braintrust.dev/app/~/logs) and select `coding-agent-insights`. Each new session appears as a root trace. Topics creates facet summaries in the background, and the scheduled Loop automations look for recurring evidence across the accumulated sessions.

### Import valuable existing sessions

If you have a local Codex session that would add useful evidence, run:

```bash
bt trace import codex "<SESSION_ID>" --prefer-profile
```

Find a session ID by running `codex resume` and copying it from the session picker. For Claude Code, replace `codex` with `claude` and use an ID from its resume command.

New and imported traces do not produce findings immediately. Once facet values appear in [**<Icon icon="activity" /> Logs**](https://www.braintrust.dev/app/~/logs), go to [**<Icon icon="scan-search" /> Patterns**](https://www.braintrust.dev/app/~/patterns) and click **Analyze patterns** to queue a fresh run.

## Extend the setup (optional)

You now have the core active observability workflow. Use the following extensions when you want to adapt the analysis or send its results to your team.

### Customize the analysis

Use Loop to adapt the installed facets and automations to the questions your team wants to answer. Go to [**<Icon icon="blend" /> Loop**](https://www.braintrust.dev/app/~/loop) and ask it to evaluate both against recent coding-agent traces:

```text
Review the coding-agent facets and automations in this project against recent traces. Identify noisy classifications, missing analysis, and recurring-analysis settings that should change. Propose and test improvements to both resources, then show me the changes before applying them.
```

Loop can drive facet creation and testing as well as automation customization. Review its proposed changes and approve the create or update actions you want to keep.

To edit an automation directly, go to **<Icon icon="settings-2" /> Settings** > [**<Icon icon="radio" /> Automations**](https://www.braintrust.dev/app/~/configuration/automations) and select **Coding Agent Improvements Discovery**, **Cost Report**, or **Failure Pattern Discovery**. You can change its instructions, model, reasoning effort, schedule, lookback window, or tool permissions. Save your changes, select **Run now**, and inspect **Past runs** to confirm that the output answers the questions you care about.

The included JSON remains a reusable starting point for new projects. Changes you approve in Loop or make in the app update the live facets and automations directly.

### Send automation output to Slack

Connect Slack under **<Icon icon="settings-2" /> Settings** > [**<Icon icon="toy-brick" /> Integrations**](https://www.braintrust.dev/app/~/configuration/org/integrations). Then go to **<Icon icon="settings-2" /> Settings** > [**<Icon icon="radio" /> Automations**](https://www.braintrust.dev/app/~/configuration/automations) and select **Coding Agent Improvements Discovery**.

In **Destinations**, open the **Destination** menu and select **Send to Slack**. Choose the workspace and channel, then use this **Formatting prompt**:

```text
Summarize the highest-confidence coding-agent improvement patterns. For each pattern, include the evidence, impact, and next action. State clearly when no pattern meets the evidence threshold.
```

Save the automation and select **Run now**. When the run finishes, the selected channel receives the formatted report. The automation also remains on its daily schedule, so later runs use the newest 30-day evidence window.

The Slack destination is configured after the JSON push because workspace and channel identifiers belong to one Braintrust organization and should not be distributed in a portable template.

## Troubleshooting

- If `bt observability template` is missing, run `command -v bt`. Reinstall with the command from Setup and put `~/.local/bin` first in `PATH` for the shell.
- If a template push reports that a facet or Loop automation already exists, rerun it with `--force` after confirming that you want to replace the matching resources.
- If `coding-agent-insights` already exists, skip `bt projects create` and run the `bt switch` command.
- If Codex reports a marketplace clone timeout, rerun `bt trace setup codex --prefer-profile`. A repeated `fatal: early EOF` indicates a Git transport or network problem rather than a Braintrust project configuration error.
- If traces do not appear, restart the agent after plugin setup and confirm that the setup command selected `coding-agent-insights`.
- If `bt trace import` cannot find a session, copy the complete ID from the agent's resume command and run the import on the machine that contains the transcript.
- If **Send to Slack** is unavailable, [enable the Slack integration](/docs/admin/organizations#enable-slack-integration) for the organization first.
- If the automation cannot call its model, configure that model under AI providers or select an available model in the automation editor.

## Recap

You've built one Braintrust project that collects new and imported coding-agent traces, classifies context debt, failure modes, and skill invocation failures through Topics, discovers recurring Patterns with two scheduled Loop automations, and generates a scheduled cost report. The portable active observability template makes the same analysis reproducible across projects, while the optional Loop and Slack workflows let each team adapt the analysis and delivery.
