# Active observability for coding agents

In this cookbook, you'll build a shared Braintrust project that turns coding-agent sessions into recurring insights. Braintrust tracing sends your instrumented coding agents to one project, custom facets classify each session, and scheduled Loop automations review the evidence over time.

Along the way, you'll:

- Instrument your coding agents and send their traces to the same Braintrust project.
- Install a portable active observability configuration with the `bt` CLI.
- Import an existing coding-agent session so the analysis starts with data.
- Optionally use Loop to create and refine facets from your coding-agent traces.
- Optionally send automation runs to a Slack channel.

<Note>
  This cookbook uses the `bt active-observability-config` command. The setup
  verifies that your installed CLI includes it before you configure the project.
</Note>

## Setup

Clone the cookbook and install the latest stable `bt` CLI. This path keeps the installer-managed binary ahead of repository-local or package-managed copies for the rest of the shell session.

You'll need:

- A [Braintrust account](https://www.braintrust.dev/signup) with permission to create projects and automations.
- An [AI provider](https://www.braintrust.dev/app/settings?subroute=secrets) configured in Braintrust for the model used by the automations.
- One or more supported coding agents installed on macOS or Linux.
- A locally stored Codex or Claude Code session to import.

<Steps>

<Step title="Clone the cookbook and install bt">

```bash
git clone https://github.com/braintrustdata/braintrust-cookbook.git
cd braintrust-cookbook/examples/CodingAgentInsights
curl -fsSL https://bt.dev/cli/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"
hash -r
```

The installer fetches the latest stable release instead of a version pinned by the repository you are tracing.

</Step>

<Step title="Authenticate with Braintrust">

```bash
bt login --oauth
```

Complete the browser flow. The saved OAuth profile lets the tracing plugins refresh credentials without putting an API key in your shell history.

</Step>

<Step title="Verify the CLI">

```bash
command -v bt
bt active-observability-config --help
```

You should see output that starts with:

```text
<home-directory>/.local/bin/bt
Pull and push facets and Loop automations as one active observability config
```

If the first line points into the repository or a package cache, repeat the `export PATH` command in the same shell. If `active-observability-config` is not recognized, run the installer again and confirm that `command -v bt` resolves to the installer-managed binary.

</Step>

</Steps>

You're now ready to instrument your coding agents.

## 1. Instrument your coding agents

Create a project for coding-agent traces, store that context in the cookbook directory, and install tracing for the agents you use. Replace `<YOUR_ORG>` with your Braintrust organization name. The commands below instrument Claude Code and Codex as examples. `bt trace setup` also supports OpenCode and Pi.

```bash
bt projects create coding-agent-insights --org "<YOUR_ORG>" --prefer-profile
bt switch "<YOUR_ORG>/coding-agent-insights" --local --prefer-profile
bt trace setup claude --prefer-profile
bt trace setup codex --prefer-profile
```

Each setup command ends with an instruction to restart the coding agent. The command stores the selected profile, organization, and project in the plugin's tracing route, so every agent you instrument sends sessions to `coding-agent-insights`.

Restart each agent you instrumented, then complete one representative coding task in each. Open the [Logs](https://www.braintrust.dev/app/~/logs) page for `coding-agent-insights`.

You should see a root trace from each agent. If only one agent appears, restart the missing agent and rerun its `bt trace setup` command from the cookbook directory.

Your instrumented coding agents now report to the same project, which gives the facets and automations one consistent stream of sessions to analyze.

## 2. Configure active observability

Push the included active observability configuration to the active project. The included automations become active after the push, call `gpt-5.5` on a daily schedule, and create or update Patterns when evidence meets their thresholds.

```bash
bt active-observability-config push active-observability-config.json --prefer-profile
```

You should see:

```text
Pushed active observability config to 'coding-agent-insights' (4 facets, 2 Loop automations)
```

The configuration creates these resources:

- **Coding Agent Context Debt** identifies reusable context that a user had to supply after work began, such as missing repository guidance, architecture knowledge, or environment detection.
- **Primary failure mode.** Classifies the most important visible issue in each run, including unresolved tests, incorrect scope, incomplete work, and wasted effort.
- **Skill invocation failure mode** diagnoses material failures caused by a verified skill invocation, such as using the wrong skill or ignoring its required workflow.
- **Workstream** groups sessions by their durable product or project initiative instead of the immediate task.
- **Failure Pattern Discovery** reviews the previous seven days of failure-mode classifications, validates recurring findings against raw traces, and creates or updates Braintrust Patterns when the evidence meets its threshold.
- **coding agent improvements discovery** reviews a 30-day window across Topics, raw traces, and existing Patterns to find recurring opportunities to improve coding agents.

`bt active-observability-config push` replaces matching facets by slug and matching automations by name. You can rerun the command without creating duplicates.

The project now has a repeatable analysis layer on top of its coding-agent traces.

## 3. Import existing traces

Seed the project with an existing Codex session so the facets and automations have data to analyze immediately. Run `codex resume` and copy a session ID from the session picker, then import it:

```bash
bt trace import codex "<SESSION_ID>" --prefer-profile
```

The command exits without output after the import finishes. Go to [**<Icon icon="activity" /> Logs**](https://www.braintrust.dev/app/~/logs) and select the `coding-agent-insights` project. You should see the imported session as a root trace.

If the CLI cannot find the session, confirm that you copied the complete resume ID and that its transcript is stored on the same machine. To import a Claude Code session instead, replace `codex` with `claude` and use an ID from its resume command.

The project now has historical data for Topics and the scheduled Loop automations, so you do not need to wait for new coding-agent sessions before reviewing the setup.

## Extend the setup (optional)

You now have the core active observability workflow. Use the following extensions when you want to adapt the analysis or send its results to your team.

### Customize the analysis

Use Loop to adapt the installed facets to the questions your team wants to answer. Go to [**<Icon icon="blend" /> Loop**](https://www.braintrust.dev/app/~/loop) and ask it to evaluate the facets against recent coding-agent traces:

```text
Review the coding-agent facets in this project against recent traces. Identify noisy classifications and gaps, then propose new facets or improvements to the existing facets. Test each change against representative traces before saving it.
```

Loop can create and test facets and preprocessors, then show each proposed resource in its workspace. Review the proposed changes and approve the create or update actions you want to keep.

To customize the recurring analysis, go to **<Icon icon="settings-2" /> Settings** > [**<Icon icon="radio" /> Automations**](https://www.braintrust.dev/app/~/configuration/automations) and select **Failure Pattern Discovery** or **coding agent improvements discovery**. Change its instructions, model, reasoning effort, schedule, lookback window, or tool permissions. Save your changes, select **Run now**, and inspect **Past runs** to confirm that the report answers the questions you care about.

The included JSON remains a reusable starting point for new projects. Changes you make in the app update the live facets and automations directly.

### Send automation output to Slack

Connect Slack under **<Icon icon="settings-2" /> Settings** > [**<Icon icon="toy-brick" /> Integrations**](https://www.braintrust.dev/app/~/configuration/org/integrations). Then go to **<Icon icon="settings-2" /> Settings** > [**<Icon icon="radio" /> Automations**](https://www.braintrust.dev/app/~/configuration/automations) and select **coding agent improvements discovery**.

In **Destinations**, open the **Destination** menu and select **Send to Slack**. Choose the workspace and channel, then use this **Formatting prompt**:

```text
Summarize the highest-confidence coding-agent improvement patterns. For each pattern, include the evidence, impact, and next action. State clearly when no pattern meets the evidence threshold.
```

Save the automation and select **Run now**. When the run finishes, the selected channel receives the formatted report. The automation also remains on its daily schedule, so later runs use the newest 30-day evidence window.

The Slack destination is configured after the JSON push because workspace and channel identifiers belong to one Braintrust organization and should not be distributed in a portable template.

## Troubleshooting

- If `bt active-observability-config` is missing, run `command -v bt`. Reinstall with the command from Setup and put `~/.local/bin` first in `PATH` for the shell.
- If `coding-agent-insights` already exists, skip `bt projects create` and run the `bt switch` command.
- If Codex reports a marketplace clone timeout, rerun `bt trace setup codex --prefer-profile`. A repeated `fatal: early EOF` indicates a Git transport or network problem rather than a Braintrust project configuration error.
- If traces do not appear, restart the agent after plugin setup and confirm that the setup command selected `coding-agent-insights`.
- If `bt trace import` cannot find a session, copy the complete ID from the agent's resume command and run the import on the machine that contains the transcript.
- If **Send to Slack** is unavailable, [enable the Slack integration](/docs/admin/organizations#enable-slack-integration) for the organization first.
- If the automation cannot call its model, configure that model under AI providers or select an available model in the automation editor.

## Recap

You've built one Braintrust project that collects new and imported coding-agent traces, classifies context debt, failure modes, skill invocation failures, and workstreams, then reviews recurring evidence with two scheduled Loop automations. The portable active observability configuration makes the same analysis reproducible across projects, while the optional Loop and Slack workflows let each team adapt the analysis and delivery.
