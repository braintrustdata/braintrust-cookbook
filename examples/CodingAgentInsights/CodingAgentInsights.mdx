# Build a coding agent insights project

In this cookbook, you'll build a shared Braintrust project that turns Claude Code and Codex sessions into recurring coding-agent insights. Braintrust tracing sends both agents to one project, custom facets classify reusable improvement opportunities, and a scheduled Loop automation reviews the evidence over time.

Along the way, you'll:

- Route Claude Code and Codex traces to the same Braintrust project.
- Install a portable analytics configuration with the `bt` CLI.
- Adapt facet prompts, analysis windows, and automation instructions to your team.
- Send each automation run to a Slack channel.

<Note>
  This cookbook uses the `bt analytics-config` command. The setup verifies that
  your installed CLI includes it before you configure the project.
</Note>

## Setup

Clone the cookbook and install the latest stable `bt` CLI. This path keeps the installer-managed binary ahead of repository-local or package-managed copies for the rest of the shell session.

You'll need:

- A [Braintrust account](https://www.braintrust.dev/signup) with permission to create projects and automations.
- An [AI provider](https://www.braintrust.dev/app/settings?subroute=secrets) configured in Braintrust for the model used by the automation.
- Claude Code and Codex installed on macOS or Linux.

<Steps>

<Step title="Clone the cookbook and install bt">

```bash
git clone https://github.com/braintrustdata/braintrust-cookbook.git
cd braintrust-cookbook/examples/CodingAgentInsights
curl -fsSL https://bt.dev/cli/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"
hash -r
```

The installer fetches the latest stable release instead of a version pinned by the repository you are tracing.

</Step>

<Step title="Authenticate with Braintrust">

```bash
bt login --oauth
```

Complete the browser flow. The saved OAuth profile lets the tracing plugins refresh credentials without putting an API key in your shell history.

</Step>

<Step title="Verify the CLI">

```bash
command -v bt
bt analytics-config --help
```

You should see output that starts with:

```text
<home-directory>/.local/bin/bt
Pull and push facets and Loop automations as one analytics config
```

If the first line points into the repository or a package cache, repeat the `export PATH` command in the same shell. If `analytics-config` is not recognized, run the installer again and confirm that `command -v bt` resolves to the installer-managed binary.

</Step>

</Steps>

You're now ready to route your coding agents to one project.

## 1. Route your coding agents to one project

Create a project for coding-agent traces, store that context in the cookbook directory, and install the tracing plugins. Replace `<YOUR_ORG>` with your Braintrust organization name.

```bash
bt projects create coding-agent-insights --org "<YOUR_ORG>" --prefer-profile
bt switch "<YOUR_ORG>/coding-agent-insights" --local --prefer-profile
bt trace setup claude --prefer-profile
bt trace setup codex --prefer-profile
```

Each setup command ends with an instruction to restart the coding agent. The command stores the selected profile, organization, and project in the plugin's tracing route, so both agents send sessions to `coding-agent-insights`.

Restart Claude Code and Codex, then complete one representative coding task in each. Open the [Logs](https://www.braintrust.dev/app/~/logs) page for `coding-agent-insights`.

You should see a root trace from each agent. If only one agent appears, restart the missing agent and rerun its `bt trace setup` command from the cookbook directory.

Both coding agents now report to the same project, which gives the facets and automation one consistent stream of sessions to analyze.

## 2. Configure coding-agent analytics

Push the included analytics configuration to the active project. The included automation becomes active after the push, calls `gpt-5.5` on a daily schedule, and can create or update Patterns when evidence meets its threshold.

```bash
bt analytics-config push analytics-config.json --prefer-profile
```

You should see:

```text
Pushed analytics config to 'coding-agent-insights' (2 facets, 1 Loop automations)
```

The configuration creates these resources:

- **Coding Agent Context Debt** identifies reusable context that a user had to supply after work began, such as missing repository guidance, architecture knowledge, or environment detection.
- **Identify Skills** finds traces that demonstrate a reusable, multi-step workflow worth packaging as an agent skill.
- **Coding agent improvements discovery** reviews a 30-day window every day, validates recurring opportunities against raw traces, and creates or updates Braintrust Patterns only when the evidence meets its threshold.

`bt analytics-config push` replaces matching facets by slug and matching automations by name. You can rerun the command after editing the file without creating duplicates.

The project now has a repeatable analysis layer on top of its coding-agent traces.

## 3. Customize the analysis

Pull the live configuration before editing it so your local copy includes changes made in the Braintrust UI:

```bash
bt analytics-config pull --output analytics-config.local.json --prefer-profile
```

Edit `analytics-config.local.json` to match the questions your team wants to answer:

- Change `facets[].function_data.prompt` to define the evidence and output format for each classification.
- Change `facets[].function_data.no_match_pattern` when the facet uses a different empty-result marker.
- Change `automations[].config.loop.prompt` to adjust the analysis workflow, evidence threshold, or final report.
- Change `automations[].config.window.window_seconds` and `automations[].config.window.schedule` to control the lookback window and frequency.
- Change `automations[].config.loop.model` and `reasoning_effort` to use a model available through your Braintrust AI providers.

Keep each facet's `slug` stable when you intend to update it. Changing the slug creates a separate facet. Keep the automation `name` stable for the same reason.

Push your edited copy:

```bash
bt analytics-config push analytics-config.local.json --prefer-profile
```

You should see the same resource counts as the initial push. Open [custom facets](/docs/observe/topics/custom-facets) and [Automations](https://www.braintrust.dev/app/~/configuration/automations) to review the updated prompts and schedule.

Your checked-in JSON is now the portable source for the project's analytical behavior. Review `actions` before committing an exported config because destinations can contain organization-specific integration and channel identifiers.

## 4. Send automation output to Slack

Connect Slack under [**Settings > Integrations**](https://www.braintrust.dev/app/~/configuration/org/integrations). Then open [**Settings > Automations**](https://www.braintrust.dev/app/~/configuration/automations) and select **Coding agent improvements discovery**.

In **Destinations**, open the **Destination** menu and select **Send to Slack**. Choose the workspace and channel, then use this **Formatting prompt**:

```text
Summarize the highest-confidence coding-agent improvement patterns. For each pattern, include the evidence, impact, and next action. State clearly when no pattern meets the evidence threshold.
```

Save the automation and select **Run now**. When the run finishes, the selected channel receives the formatted report. The automation also remains on its daily schedule, so later runs use the newest 30-day evidence window.

The Slack destination is configured after the JSON push because workspace and channel identifiers belong to one Braintrust organization and should not be distributed in a portable template.

## Troubleshooting

- If `bt analytics-config` is missing, run `command -v bt`. Reinstall with the command from Setup and put `~/.local/bin` first in `PATH` for the shell.
- If `coding-agent-insights` already exists, skip `bt projects create` and run the `bt switch` command.
- If Codex reports a marketplace clone timeout, rerun `bt trace setup codex --prefer-profile`. A repeated `fatal: early EOF` indicates a Git transport or network problem rather than a Braintrust project configuration error.
- If traces do not appear, restart the agent after plugin setup and confirm that the setup command selected `coding-agent-insights`.
- If **Send to Slack** is unavailable, [enable the Slack integration](/docs/admin/organizations#enable-slack-integration) for the organization first.
- If the automation cannot call its model, configure that model under AI providers or select an available model in the automation editor.

## Recap

You've built one Braintrust project that collects Claude Code and Codex traces, classifies actionable context and skill opportunities, and reviews recurring evidence on a schedule. The portable analytics configuration makes the same analysis reproducible across projects, while the Slack destination keeps environment-specific routing out of the shared file.
